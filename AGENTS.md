# AGENTS.md — Knowledge Base System (RAG + AI Agent)

## Architecture

- **Two-tier app**: `backend/` (FastAPI + LangGraph + ChromaDB) + `frontend/` (Vue 3 + Pinia + Vite SPA)
- **Backend entrypoint**: `backend/main.py` — FastAPI app, lifespan calls `ensure_runtime_state`
- **Runtime wiring** (`backend/app/runtime.py`): `_load_env_to_os()` → VectorStore → LocalEmbeddings → Retriever → Reranker → SkillLoader → PluginLoader → RAGAgent
- **Filesystem layer** (`backend/app/filesystem/`): rewritten to mirror opencode `@opencode-ai/core/filesystem` — `fsutil.py` (FSUtil path/mime/glob helpers), `shell.py` (platform shell), `ripgrep.py` + `search.py` (glob/grep with pure-Python fallback when `rg` binary is absent — Windows env confirmed `ripgrep_binary()` → None), `filesystem.py` (FileSystem service), `watcher.py` (mtime-polling FileSystemWatcher, no native watchdog binding). Legacy modules (`core.py`/`gitignore.py`/`models.py`/`project.py`) kept; `__init__.py` re-exports both old (`get_project`/`set_project`/`ScanCache`/`Project`/`GitignoreMatcher`/`FileNode`) and new (`FileSystem`/`FileSystemWatcher`/`RawMatch`/`DirEntry`) names so `runtime.py` and `file_tools.py` imports are unchanged.
- **Agent flow** (`backend/app/agent/graph.py`): LangGraph StateGraph — `retrieve` → `rerank` (optional) → `generate`
  - `retrieve` checks `state.use_vector_db`; if `false`, skips retrieval entirely
  - `generate` calls `litellm.acompletion`, supports tool-call loops (max 10 rounds)
- **Config**: `backend/app/config.py` reads `backend/.env` via pydantic-settings with `extra="allow"` (non-Settings env vars allowed)
- **Frontend routes**: `/multi-agent` (default), `/documents`, `/skills`, `/plugins`, `/vectors`, `/generated`, `/monitoring`. Single-agent (`/chat`, `/m`) and mobile views were removed — multi-agent is the ONLY chat entry.

## Developer Commands

```powershell
.venv\Scripts\python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000 --reload

```

## Key Conventions & Gotchas

### Backend
- **Python 3.14+** required (`.python-version`), **use `.venv\Scripts\python.exe`** directly (activate fails in subprocesses)
- **`.env` injected into `os.environ`** at startup by `runtime.py:_load_env_to_os()` so plugins can read env vars via `os.environ.get()`
- **LLM calls** need a real `LLM_API_KEY` in `.env`; LiteLLM cost-map fetch failure is non-blocking (falls back to local backup)
- **Reranker model** downloads **ModelScope-first** (HF fallback) via `app/utils/model_download.py:download_model`; in network-restricted envs set `ENABLE_RERANKER=false` in `.env` or pre-download via ModelScope:
  ```powershell
  modelscope download --model cross-encoder/ms-marco-MiniLM-L6-v2 --local_dir data/models/cross-encoder/ms-marco-MiniLM-L6-v2
  ```
  **Runtime degradation**: if `Reranker()` construction or `rerank()` prediction fails, the pipeline degrades (no rerank, order preserved) instead of crashing startup or the query — retriever sub-chains also degrade independently (vector failure → BM25-only)
- **Embedding model** (default: `BAAI/bge-small-zh-v1.5`) locally cached; English fallback `all-MiniLM-L6-v2`. Download via ModelScope:
  ```powershell
  modelscope download --model AI-ModelScope/bge-small-zh-v1.5 --local_dir data/models/BAAI/bge-small-zh-v1.5
  ```
- **ChatRequest** includes `use_vector_db: bool = False` (default off; frontend toggle per-message). Also accepts `files: list[FileContent]` for attachments (drag/drop/paste/paperclip from `ChatInput.vue`) and `directory` (session-bound working dir / opencode `ctx.directory`; used when creating a new session on first message). `FileContent` = `{filename, data (pure base64, no data URL prefix), mime_type}` (`app/models/schemas.py`).
- **Chat attachments → model** (F8 backend, LangChain document loaders): `chat.py` threads `body.files` into the supervisor payload (`chat.py:456/590`) and into persistence (`_persist_multi_agent` stores `data.files` on the user message). Supervisor forwards the payload (incl. `files`) to every sub-agent. `rag`/`code` both route through `graph.py` which splits attachments via `_attachment_parts` (`graph.py:219`): `image/*` → multi-modal `image_url` data blocks; everything else (pdf/docx/xlsx/txt/md/csv/json…) is parsed through **`app/agent/attachment_loader.py`** `attachment_context_text()` and inlined as text context in the user message (6K-char budget). `web_search` injects the same attachment text into its synthesis prompt (never drops files). **Deps**: `langchain-community` (TextLoader/PyPDFLoader) + custom `python-docx`/`openpyxl` loaders (backend has those libs; `langchain-community` is sunset so the custom loaders in `attachment_loader.py` are the fallback path). Unknown/binary/oversized attachments degrade to a one-line hint, never crash the conversation. History replay: `getConversation` maps `data.files → msg.files`, `loadConversation` restores `msg.files` from the server.
- **Chat SSE streaming (multi-agent only)**: frontend calls `POST /api/chat/multi-agent/stream`; backend emits SSE events: `queued`, `routing`, `agent_start`, `agent_step`, `agent_stream`, `agent_done`, `agent_error`, `done`, `error`, `permission_request`. SSE error events include `retryable`, `status_code`, `error_type` fields for frontend retry logic. Non-streaming fallback at `POST /api/chat/multi-agent`. The legacy single-agent endpoints (`/api/chat/`, `/api/chat/stream`, `/api/chat/stream/status`) are **removed**.
- **Supervisor routing whitelist** (`app/agent/supervisor.py`): `ROUTABLE_AGENTS = {"rag", "web_search", "code"}`. Decompose validation + LLM prompt only expose routable agents; `handle_message` re-filters subtasks and falls back to `rag`. Prevents LLM returning `"supervisor"` (registered on the bus) causing self-recursive routing → `Agent 'supervisor' did not respond in time`. **Decompose robustness**: `_llm_decompose` validates the JSON output via `_validate_subtasks` (whitelist + shape check + max 3) and does one few-shot fix retry (attempt 1 rebuilds the prompt with the parse error injected, `for attempt in range(2)`) before falling back to `rag`. **Sub-agent timeouts** are env-configurable: `SUB_AGENT_TIMEOUT` (default `150s`, supervisor→sub-agent wait in `_route_to`/`_execute_parallel`), `SUB_AGENT_TIMEOUT_EXTENDED` (default `300s`, applied to tool-intensive agents in `EXTENDED_TIMEOUT_AGENTS`, default `code`) and `SUPERVISOR_TIMEOUT` (default `300s`, endpoint→supervisor wait in `/multi-agent` and `/multi-agent/stream`). Rag generation latency is 5–60s+ (DeepSeek variance + tool loops), so 60s was too tight — `Agent '<agent>' did not respond in time` means that sub-agent exceeded the wait. **Graded timeout**: `AgentBus.send_and_wait` supports grace extensions — if the sub-agent is still active (event loop heartbeat within `grace_window`) at deadline, the wait is extended once per `grace_extensions`. **Error delivery**: sub-agent errors are delivered to the waiting caller as `AgentMessage(type="error")` (payload carries `error`/`error_type`/`completed_steps`), NOT raised as bare exceptions — supervisor `_route_to`/`_execute_parallel` transparently forward the payload.
- **Sub-agent tools + permission bridge** (`app/agent/sub_tools.py`): `code`/`web_search` now use `tool_loop_chat` (LLM tool-call loop, ≤8 rounds) with workspace filesystem tools (`tool_ls/read_file/glob/grep/write_file/append_file/edit_file/delete_file/rename_file/execute/apply_patch`). `run_tool` reuses `app/tools/file_tools.py` (same PermissionManager); on `NeedsPermission` it emits a `permission_request` event to the event queue (forwarded to the multi-agent SSE stream) and **awaits** the user's approval via `mgr.await_decision` (mirrors `graph.py:_execute_tool`) — `allowed` adds a temp approval and retries the tool, `denied`/`expired` returns a denial message to the LLM; no event queue → immediate denial. Tool args are filtered to the function signature (LLM-typed strings no longer crash). Tool results are envelope-unwrapped via `fs.unwrap()`. **Tool results bounded like the main agent** (not a fixed 1500-char slice): `bound_tool_output` truncates oversized output, persists the full text to `data/truncation/`, and hints at `tool_read_file(offset)`/`tool_grep` continuation — so large-file reads inside sub-agents never lose information.
- **Multi-agent realtime events** (see `docs/multi-agent-realtime-events-design.md`): `/multi-agent/stream` streams per-sub-agent events `agent_start`/`agent_step`/`agent_done`/`agent_error` (frontend keys agents by `agent_id`, steps upserted by `step_id`). Event bridge = request-level `AgentEventCollector` (`app/agent/stream_events.py`) passed to sub-agents via `AgentMessage.payload["_event_queue"]` (supervisor forwards payload unchanged). `RAGAgentWrapper` wraps it as `TaggedEventQueue` handed to `RAGAgent.invoke(event_queue=...)` so `graph.py:_push_event` outputs become `agent_step` (tool_output/tool_heartbeat dropped; permission_request passed through to the frontend, which surfaces it via the shared `PermissionDialog` approval panel — approved requests retry the tool, denied/timed-out ones return a denial to the agent). Final `done` event + persisted assistant message carry `agents` snapshot (built by `collector.agents_snapshot()`) so history replay shows agent panels.
- **Execution loop guards** (`app/agent/graph.py` `_generate`): `MAX_STEPS` (default `24`, primary cap aligned with opencode `agent.steps`; effective cap = `min(MAX_TOOL_ROUNDS, MAX_STEPS)`, `MAX_TOOL_ROUNDS` default `8` [token 优化 v9] is a hard backstop) — on the last allowed round a `MAX_STEPS_PROMPT` is injected **as an assistant-role message** (aligned with opencode `prompt.ts:1281`) and tools are disabled for the final call, forcing a structured "已完成/未完成/下一步" summary. **Doom-loop detection**: `DOOM_LOOP_THRESHOLD` (default `3`) — identical `tool+args` fingerprint repeated N consecutive rounds injects a strategy-change prompt; **escalation**: after `DOOM_LOOP_MAX_STRIKES` (default `2`) repeated detections it stops prompting and forces the structured summary with tools disabled (opencode-equivalent of `permission.ask(doom_loop)` → deny → stop). Both aligned with opencode `max-steps.ts` / `processor.ts`.
- **Task completion = finish-driven** (`graph.py` `_generate`): reads `response.choices[0].finish_reason` and normalizes via `_normalize_finish_reason` to the opencode `FinishReason` six-value enum (`stop`/`length`/`tool-calls`/`content-filter`/`error`/`unknown`, aligned with `llm/src/schema/ids.ts`). Loop continues while `msg.tool_calls` present or `finish_reason == "tool-calls"` (only `tool-calls` keeps the loop alive, matching `prompt.ts:1113`); `length` appends a truncation notice to the answer; `content-filter` turns the answer into an explicit error surfaced via `steps` events. See `docs/task-completion-design.md`.
- **Long-task / truncation prevention** (aligned with opencode `transform.ts:maxOutputTokens` + file-based output): per-call output cap is `settings.llm_max_tokens` (`LLM_MAX_TOKENS`, default `8192` [token 优化 v9], was `16384`) — do NOT hardcode in `_llm_call` (`graph.py:447`); `LONG_CONTENT_FILE_RULE` in `backend/app/agent/tools.py` (appended to both the no-KB prompt in `build_system_prompt_no_kb` and the KB prompt via `graph.py:_system_prompt_with_kb`) forces the model to write content > ~500 chars to files (`tool_write_file`/`tool_append_file`/generator plugins) and keep replies to a summary, so single-round output rarely hits `length`. `length` is intentionally NOT auto-continued (matches opencode). See `docs/long-task-design.md`.
- **Tool output truncation + prune** (aligned with opencode `tool/truncate.ts` + `session/compaction.ts`): `bound_tool_output` (`app/context/tool_output.py`) truncates new tool outputs (default 200 lines/32KB; tight_limits for `tool_grep` 100/16KB, `tool_execute` 300/32KB, `tool_read_file` 200/32KB) and **writes the full output to `data/truncation/tool_*.txt`** when truncated, appending a hint to `tool_read_file(offset)`/`tool_grep` so info is never lost — start-up `main.py` lifespan runs `cleanup_truncated()` (7-day retention, opencode `RETENTION`). **Both the main agent (`graph.py`) and sub-agents (`sub_tools.py` `run_tool`) bound tool results this way** (sub-agents replaced the old fixed 1500-char slice). `prune_tool_outputs` back-reclaims older round tool outputs to stubs (protect/minimum thresholds), and **the stub also persists the original content to `data/truncation/`** so the model can re-read it. **`prune_tool_outputs` 的 `tail_turns` 按「工具调用轮次」计数**（一个 `assistant`+`tool_calls` 消息计一轮，保护其之后的所有消息）——NOT user turns: a single request usually has one user message, so user-turn protection would exempt every tool output and prune never fires. **Threshold linkage** [token 优化 v12]: effective prune protect = `min(settings.tool_output_protect_tokens, compaction_threshold_tokens()//2)`, minimum = protect//2 (via `app/context/budget.py:prune_protect_tokens/prune_minimum_tokens`) — this guarantees prune fires **before** compaction (the raw `TOOL_OUTPUT_PROTECT_TOKENS` default 40K/20K was designed for 200K+ context and never triggered ahead of a 12K compaction threshold). **Compaction input capping** (`app/context/compaction.py` `_summarize`): each old tool message content is truncated to `TOOL_OUTPUT_MAX_CHARS=2000` before feeding the summarizer (opencode `TOOL_OUTPUT_MAX_CHARS`, marker `[Tool output truncated for compaction: omitted N chars]`). **[token 优化 v14] `COMPACTION_THRESHOLD_TOKENS=0`** (auto = 0.6 × usable ≈ 91K with `MAX_CONTEXT_TOKENS=160000`): the old 12K threshold was set when context was 24K; at 160K it caused premature compaction → cache invalidation (cache_hit ~41%) + repeated local-ollama compaction calls. Auto ratio aligns with opencode default.
- **Model name auto-prefixing** (`graph.py:216-220`): if `model` has no `/`, prepends `deepseek/` or `openai/` based on `api_base` — always use full names like `deepseek/deepseek-v4-flash`
- **AgentState.use_vector_db** (`graph.py:78`): when `false`, `_retrieve` returns empty context immediately — no KB search
- **Tool call JSON error handling** (`graph.py:244-246`): `json.loads(tc.function.arguments)` wrapped in try/except — malformed args return error to LLM instead of crashing
- **Skills**: Markdown files in `backend/skills/*.md` or `backend/skills/<name>/SKILL.md` with YAML frontmatter. Both formats mixed.
- **Plugins**: Python files in `backend/plugins/*.py`, functions named `tool_*` are auto-registered
  - Enabled state: presence of `backend/plugins/<module>.enabled` file (not YAML frontmatter)
  - Disabled by default: `example_plugin.py`, `file_reader.py` (no `.enabled` file)
- **Plugin tool name** format: `plugin_<PLUGIN_NAME>_<func_name>` where `PLUGIN_NAME` matches the `PLUGIN_NAME` attribute in the `.py` file (may contain hyphens, e.g. `plugin_internet-search_tool_internet_search`)
- **filesystem plugin** (`plugin_filesystem_tool_*`): file ops — `tool_ls` (gitignored 项不列出, 对齐 opencode list 语义), `tool_read_file` (text with offset/limit — limit 默认 2000 行且输出受 50KB 字节硬上限约束、超限截断提示用 offset 续读、offset 越界报错，opencode read.ts 语义; 二进制检测只读前 4KB 样本; multimodal base64 for images/audio/video/pdf; **输出格式对齐 opencode**：行前缀 `{line}: {text}`，目录列出用 `<path>/<type>directory</type>/<entries>` 分页), `tool_write_file`, `tool_append_file` (chunked append for large files), `tool_edit_file` (single or global replace — **行尾保留**: 读取/写入均用 `newline=""`, `_detect_line_ending` 按 CRLF/LF 计数检测、old/new 归一化后转换到文件行尾再匹配、UTF-8 BOM 保留, 对齐 opencode edit.ts detectLineEnding/normalizeLineEndings/convertToLineEnding, 避免 Windows 上 LF→CRLF 或 Linux 上 CRLF→LF 的静默损坏; write/append 同样 `newline=""` 原样写入), `tool_glob`/`tool_grep` (optional `path` param to search any directory — renamed from `root`, 对齐 opencode glob/grep; absolute paths returned for custom paths; grep 输出 `Found N matches` + `path:`/`  Line N: text` 分组、glob 空结果 `No files found`, 对齐 opencode grep.ts/glob.ts toModelOutput), `tool_execute` (shell, max 300s timeout default / 600s cap; **supports pipes/redirects/&&/subshells via real shell**, 对齐 opencode bash 语义; param is `workdir`, NOT `work_dir`; **启动失败错误报告**: streaming 路径 `graph.py:_execute_tool_streaming` 与同步路径都返回 `Error starting command: <detail>` / `Error executing command: <detail>`，其中 `<detail>` 在异常消息为空时回退到 `repr(e)`/异常类型，并附带实际 `Command:` 与 `Workdir:` —— 避免 Windows 下 `create_subprocess_*` 抛空消息异常时用户拿到毫无信息的报错; **streaming 路径已改为 Popen+线程桥接**（对齐 opencode shell.ts 单路径语义）: `subprocess.Popen` 启动 + 后台线程逐行读管道 + `loop.call_soon_threadsafe` 推 `tool_output`/心跳回事件队列, 超时用轮询 `poll()` + 同步 `_kill_process_tree`(taskkill /T /F), 不再依赖事件循环自身的子进程能力 —— Windows + uvicorn `--reload` 下事件循环为 SelectorEventLoop（uvicorn 0.49 `loops/asyncio.py`: win32 + use_subprocess → SelectorEventLoop）, 旧实现 `asyncio.create_subprocess_*` 直接抛 `NotImplementedError` 导致「tool_execute 环境不可用」（2026-08-16 会话实锤: 连 `echo test` 都失败）; 已在 Selector/Proactor 双循环下验证 echo 流式事件、`node --check` 成功/语法错误 stderr 捕获、超时杀树无孤儿进程 全部通过; **cmd.exe 方言纠错**: LLM 训练语料偏 bash 会写 POSIX 语法给 cmd.exe（历史实锤 `.venv/Scripts/python.exe ...; echo "EXIT=$?"` → `'.venv' 不是内部或外部命令` + `$?` 字面打印）, 两层修复: ① system prompt 加 Shell dialect 说明（tools.py no-KB 条件注入 + graph.py KB 模式, os.name=="nt" 时生效）② 输出组装处检测失败签名（`不是内部或外部命令`/`is not recognized`/未展开 `$?`, file_tools.append_cmd_dialect_hint, 同步 `_format_execute_output` 与流式返回两处接入）追加 `[cmd.exe hint]`（反斜杠路径/%ERRORLEVEL%/& 替代 ;）供 LLM 下轮自纠; **子进程输出三级解码** `decode_process_output`(utf-8 严格→GBK→utf-8 replace): cmd.exe 中文报错是 GBK、node/npm 是 UTF-8, 单一编码必错一边 —— 同步 `_run_shell` 弃用 text=True 改字节管道+解码器, 流式 `_pump` 同用该解码器, 不依赖 `-X utf8`/locale)), `tool_apply_patch(patch_text)` (opencode apply_patch 语义 — `*** Begin Patch` / `*** Add File:` +`+` lines / `*** Update File:` +`-`/`+`/space lines / `*** Delete File:` / `*** End Patch`, output `Applied patch sequentially:` + `A|M|D <path>`, partial-apply failure reports applied ops; registered as a write tool so it clears the tool-output dedup cache after use). **All file tools return an envelope `{title, metadata, output}`** — consumer sites unwrap via `file_tools.unwrap(result)` (graph.py `_bound_plugin_result`, sub_tools.py `run_tool`); plain strings pass through unchanged. **Relative paths resolve against the session bound directory, else the git worktree (repo root) — NOT `backend/`** (`app/tools/file_tools.py:_workspace()` reads `get_project().worktree`; `graph.py` tool_execute `workdir` uses the same `_resolve`). `tool_ls` iterates `ScanCache` (`app/filesystem/core.py`, auto-invalidated on write/edit/delete/rename). `tool_glob`/`tool_grep` **filter out sensitive files per-match** (workspace `.env`/`*.db`/`permissions.json`, system dirs, un-authorized external paths are silently skipped). **`tool_glob`/`tool_grep` respect `.gitignore`** (opencode ripgrep 语义): `GitignoreMatcher` (`app/filesystem/gitignore.py`, 自包含实现 git 语义 — 层级 `.gitignore`/`!` 取反/尾部 `/` 仅目录/含 `/` 锚定/`**` 跨目录, 按 mtime 缓存规则) 由 `app/tools/file_tools.py:_gitignore_matcher()` 按 worktree 惰性构建; `tool_glob` 用 `matcher.glob()` 过滤、`tool_grep` 用 `matcher.walk()` **裁剪被忽略目录**（不再遍历 `node_modules`/`.venv`/`dist` 等垃圾路径）；`ScanCache` 通过构造参数 `ignored_checker=_gitignore_checker` 填充 `FileNode.ignored`（root 之外的搜索路径不忽略）。**Working directories are configured from the frontend「工作目录」panel** (persisted to `backend/data/runtime_workspaces.json`, runtime-effective, no restart) — the `.env` `EXTRA_WORKSPACES` variable is removed. Outside all workspaces: `EXTERNAL_PATH_DEFAULT` (ask/allow/deny, default `ask`); permission approval waits at most `PERMISSION_APPROVAL_TIMEOUT`s (default 60) then denies. Tool params (`offset`/`limit`/`overwrite`/`replace_all`/`context`/`count_only`/`files_only`/`timeout`/`workdir`/`patch_text`) are declared as typed schema AND coerced at runtime, so string-typed numbers from the LLM no longer crash.
- **SSRF protection** (`app/utils/ssrf.py`): all outbound HTTP from `plugins/http_client.py` and network commands in `tool_execute` (curl/wget/ssh/scp/rsync/ping/…) pass through `check_url`/`_ssrf_check_command` — blocks private/loopback/link-local/metadata (169.254.169.254 etc.) IPs AND domains that resolve to them. Set `SSRF_ALLOW_INTERNAL=true` in `.env` to bypass for local debugging. Scheme restricted to http/https.
- **Command blacklist** (`app/tools/file_tools.py:_check_command_blacklist`): interpreter commands (`python -c`, `node -e`, `powershell -Command`, `cmd /c`) get their inline arg scanned against `_DANGEROUS_PATTERNS` (os.system/subprocess/eval/urllib/socket./Invoke-Expression/whoami/curl…, case-insensitive) — the first-token whitelist alone can't stop `python -c "import os;os.system(...)"` from escaping it. Both `tool_execute` and `graph.py:_execute_tool` call it before execution. **Shell-aware segmented validation** (`file_tools.py:_validate_shell_command`): `tool_execute` supports real shell semantics (pipes/redirects/`&&`/subshells/`$(...)`/backticks/`%VAR%`), but `_split_shell_segments` (shlex `punctuation_chars=True`) splits the command at `; | || && & ( )` into simple-command segments and validates **each segment's** base command against the whitelist (env-prefix `FOO=bar` skipped), each segment runs blacklist + SSRF — so `cat x | evil` can no longer bypass the first-token whitelist. `$(...)` inner commands and backtick bodies are validated recursively. `_needs_shell` routes simple commands (no shell metachars outside quotes) through the original `shlex.split` + exec path (zero regression); complex ones run via real shell (Windows `cmd.exe`, POSIX `/bin/sh` — `shell=True`) in a new process group/session, and on timeout the **entire process tree is killed** (`_kill_process_tree` taskkill /T /F / `_async_kill_process_tree` killpg). Both `tool_execute` and `graph.py:_execute_tool_streaming` use this path.
- **Shell 重定向目标权限检查** (`file_tools.py:_check_redirect_targets_permission`): `tool_execute` 通过 `>`、`>>`、`2>`、`2>>`、`&>` 写入的外部文件现在会经过权限检查（`_extract_redirect_targets` 用 shlex 解析重定向目标路径，`_check_redirect_targets_permission` 调用 `mgr.check(path, "write")`）。`/dev/null` 等特殊设备文件跳过。同步路径（`tool_execute`）和流式路径（`graph.py:_execute_tool_streaming`）均已接入。注意：`python -c "open(...).write(...)"` 等动态写入仍无法拦截（需要进程级沙箱）。
- **Permission model & worktree** (`app/permission/manager.py`): `PermissionManager` is constructed with `workspace=backend/` (source-protection base for `app`/`plugins`/`skills`/`config`/`main.py` etc.) plus `project_worktree=<git repo root>` (from `app.filesystem.Project.from_git`, see `runtime.py`).
