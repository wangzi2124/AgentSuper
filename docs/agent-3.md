模型切换上下文保持：设计与校验规范
供 Agent 执行。按「根因 → 设计 → 校验 → 陷阱 → 落地」顺序落地，不得跳步。
核心原则：切换模型只换推理引擎，不碰记忆资产；校验不查"消息还在不在"，查"事实还答不答得出来"。

一、根因定位
切换模型丢失上下文，根因通常不在模型本身，而在两处：

上下文数据存放位置错误：历史、摘要、模型绑定混在同一层，切换时被一起重置。

切换时缺少迁移逻辑：新模型窗口更小或序列化协议不同，旧历史无法直接装入，系统选择"清空重来"。

另有一类假性丢失：消息 ID 跨协议重算，内容还在但系统认不出是同一条消息（OpenAI 与 Anthropic 对 tool_call 序列化差异是典型场景）。

结论：必须先把状态分层、ID 稳定化，再谈切换与校验。

二、设计：三层分离 + 门禁 + 原子迁移
2.1 数据分层（先解决"放在哪"）
层	放什么	不放什么
会话历史（原文）	完整消息列表，带稳定 ID	模型名、窗口大小
会话摘要	压缩后的结构化事实（含精确值）	完整 transcript 副本
模型绑定（本轮）	当前轮次实际使用的模型	历史消息的"归属模型"
模型选择（下一轮）	用户 setModel 后的目标模型	旧历史已装入新窗口的证明
迁移备份	switchModel 前的原文快照	进程退出后的长期存档
铁律：

历史消息 ID 必须跨模型、跨协议稳定。用逻辑消息的稳定哈希做 ID，与序列化协议解耦，禁止用 index 或 modelName + index。

原文与摘要分离存储。摘要迁移失败时原文必须仍在备份中。

2.2 切换门禁（switchModel 执行前，任一失败即拒绝并回滚）
目标模型窗口已知：maxContext 未知 → 拒绝切换，不允许假设"大概放得下"。

压缩配置与目标模型成对绑定：目标窗口更小 → 压缩阈值必须同步调低，否则压缩后仍超窗。禁止复用旧模型的压缩配置。

运行中轮次冻结：当前有生成中的回答 → 拒绝切换，等该轮结束（类似 OpenCode turn_running）。

预算闸不重置：maxTotalTokens / maxUsd 累计逻辑继续作用于后续轮次，切换模型不清零。

2.3 原子迁移（窗口不足时必须执行）
text
旧历史 ──分段摘要──► 会话摘要层（保留精确值：路径/命令/数字/ID）
        │
        └──原文快照──► 迁移备份（不丢弃）
新模型从 "摘要 + 近期原文" 开始工作，而非空历史
提交协议：模型绑定更新 + 摘要生效 + 备份标记可清理，三者同时成功或同时回滚。迁移失败 → 不切换模型，保持旧模型运行，记录人工核对事件。

2.4 前端状态处理（Vue 组件场景）
切换模型后不重新初始化消息列表，只更新 currentModel 字段。

消息组件 key 使用稳定 message.id，禁止 index 或 modelName + index，避免 Vue 误判为新列表而重建。

若切换触发服务端拉取历史，拉取完成前显示"正在切换模型，历史加载中"，不清空当前列表。

参考 OpenCode 已知 bug：FAST_BOOT 模式下 provider 目录未加载完就 set()，模型选择被静默跳过回退默认值——用户以为丢了上下文，实际丢的是模型选择。修复方式：set() 前等待 provider 目录就绪，失败时显式报错而非静默回退。

三、校验：三层验证法
3.1 第一层：消息完整性（切换后立即执行）
ts
const beforeIds = messageList.map(m => m.id)
await switchModel(targetModel)
const afterIds = messageList.map(m => m.id)

// 允许新增，不允许丢失；被压缩的消息查 is_compacted 标记，不要求出现在活跃列表
const lost = beforeIds.filter(id => {
  const m = messageMap.get(id)
  return !m || (!m.is_compacted && !afterIds.includes(id))
})
if (lost.length > 0) {
  rollbackModelSwitch()
  alert('消息丢失，已回滚模型切换')
}
3.2 第二层：事实召回探测（确定性，零 LLM 成本）
从历史中提取精确值（路径、ID、日期、金额、用户原话数字），切换后发起轻量探测：

text
问题：之前对话中提到的项目路径是什么？只输出路径。
期望：/workspace/agent-platform
探测失败 → 摘要迁移丢失关键信息 → 回滚并检查压缩逻辑的 enforce_precision 步骤。
探测实现可参考 Magic Context 的 ctx_search（按来源排序：记忆优先、事实次之、消息最后），不依赖模型"记得"。

3.3 第三层：区分风格差异与数据丢失（避免误报）
切换后"感觉不一样"是正常的（指令遵循、压缩策略、详略、工具调用倾向存在真实差异）。新模型不主动复述"你之前提到过 X"不代表不知道。

判定方法：拿一件确定它应该知道的事实去问。

答得出 → 风格差异，非 bug。

答不出 → 数据问题，进入第二层排查。

3.4 回归用例（加入 L4 提示词/模型测试）
python
def test_model_switch_preserves_facts(run_agent_with_model):
    run_agent_with_model("model-a", "记下：项目代号 Falcon，端口 8080，负责人张三。")
    run_agent_with_model("model-b", "切换到 model-b 继续。")
    r = run_agent_with_model("model-b", "项目代号是什么？端口是多少？")
    assert "Falcon" in r and "8080" in r
四、陷阱清单
陷阱	后果	规避
消息 ID 跨协议不稳定	系统认作新消息，重复或丢失	逻辑消息稳定哈希作 ID，与序列化协议解耦
压缩配置未随模型切换	新窗口更小，压缩后仍超窗	压缩 manager 与目标模型成对绑定
切换时清空列表再重建	用户看到"全部消失"，误报丢失	原子更新模型字段，列表原地保留
校验只查消息条数	条数对但内容被摘要错误覆盖	增加精确值探测
切换失败后状态不一致	模型已换但历史未迁移	回滚模型绑定到切换前，旧模型继续运行
set() 静默回退默认模型	用户以为丢上下文，实际丢模型选择	set() 前等 provider 就绪，失败显式报错
五、落地顺序
修数据层（前置条件）：历史/摘要/模型绑定分属不同存储，消息 ID 跨模型稳定。不做此步，后续校验无意义。

加切换门禁：窗口未知拒绝、运行中拒绝、压缩配置绑定检查、预算不重置。

实现原子迁移：分段摘要 + 原文备份 + 提交回滚。

加校验：消息完整性（即时）+ 精确值探测（切换后异步）+ 风格差异判定（人工/回归）。

加回归用例：L4 固定"模型 A 建上下文 → 切模型 B → 探测事实"黄金集。

六、验收标准
项	标准
消息 ID	跨模型、跨协议切换后不变；用稳定哈希而非 index
切换门禁	4 项检查全部生效，失败时模型回滚且旧模型可继续
迁移原子性	摘要生效、绑定更新、备份标记三者同时成功或同时回滚
完整性校验	切换后无未压缩消息丢失；压缩消息有 is_compacted 标记
事实探测	精确值（路径/ID/数字）在切换后可召回
误报控制	风格差异不触发回滚，仅数据问题触发
前端	切换后消息列表原地保留，key 使用 message.id
七、一句话记忆
切换模型只换引擎，不换记忆；历史/摘要/绑定三层分离，ID 稳定是底线；门禁先查窗口与运行态，迁移原子提交可回滚；校验查"事实还答不答得出来"，不查"消息还在不在"。
