## 一、背景与目标

本项目为「多智能体知识库 AI 助手」：后端提供多 Agent 协作（Supervisor + 子 Agent）、RAG 检索（向量 + BM25 + 章节库）、SSE 流式、工具系统；前端提供桌面端与移动端（≤768px）双轨界面。

经过代码与文档审查，项目功能完成度高，但存在**安全、数据一致性、并发、前端链路、架构可维护性、部署容错**六类短板，同时移动端界面在**视觉层级、品牌感、组件一致性**上与同类产品存在差距。

本计划的目标：

1. 消灭 P0 级安全与数据正确性风险（2~4 周）。
2. 完成数据一致性、并发与关键功能补全（2~3 个月）。
3. 重构架构、补测试、完善部署容错（3~6 个月）。
4. 同步完成移动端 UI 改版，达到「专业、统一、有品牌感」的视觉效果。

## 三、总体框架：PDCA（大环套小环）

每个大问题独立成一个小循环，整体形成持续改进机制：

- **P（Plan）**：填写问题描述、现状数据、SMART 目标、根因分析、解决方案、责任人、时间线、成功指标。
- **D（Do）**：小范围试点 → 记录观察 → 反馈 → 全量推广。
- **C（Check）**：用数据对比预期与实际差距，定位根因。
- **A（Act）**：有效方案标准化固化（写入开发规范）；无效方案调整策略；归档文档后启动下一轮。

> 每个优化项都对应一张「PDCA 卡片」（看板中维护），格式见附录 A。

## 五、移动端 UI 改版专项（与 P0 批次并行）

### 5.1 改版目标

将移动端（≤768px）从「van-cell 列表 + 单一强调色」升级为「卡片化 + 语义色彩体系 + 品牌渐变」，对齐同类产品（如各类 AI 助手 App）的视觉水准：

1. **统一设计令牌**（`--m-*` 变量体系）：全变量化，深色模式自适应。
2. **页面卡片化**：16px 圆角、柔和阴影、分组标题、统计卡。
3. **语义色彩体系**：文档=蓝、技能=紫、插件=青、向量=绿、监控=橙、工具=粉。
4. **品牌渐变**：`linear-gradient(135deg, #6d5ef1, #8b5cf6, #38bdf8)`。
5. **图标统一**：Vant 图标 + 彩色圆底容器，移除 emoji 混用。
6. **TabBar / 抽屉品牌化**：渐变胶囊激活态 + 毛玻璃品牌区。

## 六、执行与检查机制

### 6.1 优化看板

- 每个优化项在共享看板维护状态：`待办 → 试点中 → 已验证 → 已标准化`。
- 关键指标定期更新：安全测试通过率、并发错误数、前端 `!important` 数量、构建体积、移动端页面数。

### 6.2 阶段性评审

- 每两周检查一次进度；每月一次整体 PDCA 评审（变化快的团队可缩短）。
- 每次评审输出「经验教训」，有效做法写入开发规范（安全编码规范、存储访问规范、UI 令牌规范）。

### 6.3 文档同步

- 先对 `docs/聊天输入框与后端聊天链路优化清单.md` 做全面复核，标注真实状态（部分条目已落地但文档未更新），再排期剩余项，避免按过时清单白做工。
