# 多智能体编排代码地图（Supervisor 意图路由 + 子 Agent 并行流式）

> 状态：v1 草稿（后端与前端核心链路均已读码核验）
> 范围：backend/app 与 frontend/src

## 1. 全链路分层总览

前端 Vue：MultiAgentView.vue -> stores/multiAgent.ts -> api/multiAgent.ts(SSE 消费)
POST /api/chat/multi-agent/stream（另有非流式 /multi-agent）

HTTP/SSE 层：chatmod/endpoints.py
- Semaphore(MAX_CONCURRENT_AGENTS) 并发控制 + 排队，超限返回 429
- 通过 AgentBus.send_and_wait 等待 Supervisor 终态
- 消息载体 AgentMessage(source/target/type/action/payload/thread_id)

编排层：supervisor.py(facade) -> SupervisorAgent
继承链（supermod 目录）：base -> core -> decompose -> parallel
handle_message(chat) 流程：
- _decompose()：关键词快速路径 / LLM 多子任务分解
- 单子任务 -> _route_to()
- plan 命中「先规划再执行」关键词 -> _route_plan_then_build()
- 多子任务 -> _execute_parallel()：asyncio.gather 并行 + _synthesize() 汇总
- 子任务独立 thread_id(:sub:/:decomp:) 防止 Future 覆盖

子 Agent（agent_specs.py 注册）：
- build：主 Agent，RAGAgent 包装，不裁剪工具
- explore：只读工具白名单
- plan：纯 LLM，产物落盘 data/plans/<conv>/plan.md

事件回传（两条线，均带 agent_id）：
1) 增量流：stream_events.TaggedEventQueue 透传 graph 事件
   -> AgentEventCollector(事件副本上限 500 条，agents_snapshot 重建面板)
   -> SSE(text_delta 真增量直通) -> 前端 store 按 agent_id 归并 -> 面板实时渲染
2) 落库：agent_executor.PartBridgeQueue(事件 -> message_parts)
   -> SQLite 持久化，前端 IndexedDB 防抖 1.2s 同步

## 3. 运行时装配（后端）

runtime.py 的 _do_init() 中完成（main.py lifespan 启动 agent_bus.start_all()）：
- 共享内存 MemoryManager(default_ttl=300)，5 分钟过期
- 主 RAGAgent（LangGraph，无总线）由 RAGAgentWrapper(agent_id="build", heartbeat=agent_bus.touch) 包装
- 注册顺序与 id：build、explore(ExploreAgent)、plan(PlanAgent)、supervisor(SupervisorAgent)
- 主 Agent 注入 agent.task_bus = agent_bus，可自主委派子 Agent
- app.state.agent_bus 供端点使用

agent_specs.py 规格要点：
- build：primary mode；tools=None（不裁剪，走 RAGAgent 自身 graph 工具）；extended_timeout=True（长超时）
- explore：subagent；tools=_READONLY_TOOL_NAMES 只读白名单（ls/read/glob/grep）
- plan：subagent；tools=()（纯 LLM）；产物落盘 data/plans/<conv>/plan.md
- supervisor 自身不在 ROUTABLE_AGENTS 中（防自递归）；白名单 {build, explore, plan}

## 4. Supervisor 编排层（supermod/，supervisor.py 为 facade）

继承链（由底到顶）：
SupervisorAgentBase(supermod/base.py)
  -> SupervisorAgentCore(supermod/core.py)
  -> SupervisorAgentDecompose(supermod/decompose.py)
  -> SupervisorAgent(supermod/parallel.py)   <-- 对外类

- L0 base.py：ROUTABLE_AGENTS 白名单；extended_timeout_agents 分级超时；
  心跳 beat/进度 touch；_PLAN_HANDOFF_KEYWORDS 判定「先规划再执行」；短寒暄词表
- L1 constants.py：DECOMPOSE_SYSTEM_PROMPT（路由专家提示词）、
  SYNTHESIS_SYSTEM_PROMPT（汇总提示词）、SUB_RESULT_TRUNC=3000 子结果截断阈值
- L2 core.py 入口 handle_message(action=chat)：语音兜底 -> 心跳 -> _decompose()
  -> 单任务 _route_to()；plan 命中时 _route_plan_then_build()（先出计划再执行）；
  多任务 _execute_parallel()；LLM 用量 _usage 汇总；独立 thread_id(:sub: 后缀防 Future 覆盖 bug)
- L3 decompose.py 意图判定：关键词快速路径（explore 列表/plan 列表/<=24 字符寒暄直走 build）
  否则 _llm_decompose()：LLM 分解 JSON -> _validate_subtasks 校验
  （agent 白名单 + 最多 3 个子任务）；解析失败 few-shot 修复重试 1 次后回退 build
- L4 parallel.py _execute_parallel()：asyncio.gather 并行 run_one；
  fresh-context 清 history（token 优化）；每个子任务独立 thread_id(:decomp:) + 分级 timeout；
  捕获 TimeoutError 回传 completed_steps；_synthesize() 汇总
  （单结果直通不汇总；子结果截断 3000 字符；LLM 汇总多结果）

## 5. AgentBus 与流式事件

bus.py：
- register / list_agents / get_agent；send() 支持直投 response/error 到 _pending[thread_id] Future、'*' 广播
- send_and_wait(timeout, grace_extensions, grace_window)：心跳宽限续期机制
  （子 Agent 事件循环活跃则截止时间顺延，防止长任务被误杀）
- touch(agent_id, progress)：心跳 + 进度上报（进度最多 8 条），供超时回传 completed_steps
- agent_progress / cancel_pending：级联取消（对齐 opencode abort）
- run_agent() 事件循环：mailbox -> handle_message() 生成器 -> send；
  异常自动重启（递增延迟，最多 5 次重试）；对等待方投递 type="error"（携带 completed_steps），不抛裸异常

stream_events.py（并行流式的关键）：
- 事件分级常量（graph 事件 -> SSE 事件的取舍）：
  * ALLOW_STEP_EVENTS：step_start/end、tool_start/end -> 转 agent_step 事件并打 agent_id
  * TEXT_DELTA_EVENTS：message.part.delta 真增量直通（带 agent_id，前端主回答实时增量渲染）
  * PASSTHROUGH_EVENTS：permission_request 等原样透传
  * THROTTLED_HIGH_FREQ_EVENTS：tool_heartbeat 节流 >=3s/条（避免 60s 停流误判），按 step_id=tool_<name> 原位 upsert
  * DROP_HIGH_FREQ_EVENTS：tool_output 高频事件显式丢弃（防背压冲突）
- AgentEventCollector：事件副本上限 500 条（agent_step 可丢只记账，start/done/error 必留）；
  agents_snapshot() 重建各 Agent 面板快照（供前端 done/重连兜底回填）；fail_running() 超时兜底
- TaggedEventQueue：graph _push_event 只依赖 put_nowait，传入即透传，不改 graph

## 6. 落库桥接与 HTTP/SSE 端点

session/agent_executor.py：
- PartBridgeQueue：graph 事件 -> message_parts 实时落库（step_start->step-start part；
  tool_start/end -> 同一 tool part 原位 upsert；text_delta -> 累积 text part）+ 转发 SSE（事件带 part_id）
- append_agent()：落 agent part，供多 Agent 归属展示
- classify_error()：retryable / status_code / error_type 统一错误分类

api/chatmod/endpoints.py：
- 并发控制：Semaphore(MAX_CONCURRENT_AGENTS) + MAX_QUEUE_SIZE=50 排队上限（满则 429）；_queue_counter 配平
- POST /multi-agent（非流式）与 POST /multi-agent/stream（SSE）：
  均走 send_and_wait(supervisor_timeout)；body.agent_mode in {plan, explore} 时直连子 Agent 跳过 supervisor；
  payload 携带 _event_queue: collector（传输线：endpoint -> bus -> supervisor -> 子 Agent graph）
- SSE 事件类型序列：queued(排队位次) -> routing -> agent_*/增量文本 -> done(answer/sources/agents 快照/tokens/消息 id) -> error(含 classify_error 结果)
- _persist_multi_agent(...agents=agents...)：先落库拿消息 id 再发 done；主会话 + kind='task' 子会话
- _begin_task_session：登记 thread 以支持级联取消

## 7. 前端（已读码核验，核心在 stores/multiAgent.ts §494-658）

api/multiAgent.ts（SSE 消费）：
- fetch 30s 连接超时；60s stall 检测（归类 timeout，可重试）
- 429/5xx 错误分类；X-Session-Id 响应头提前透出会话 id（排队期即可触发"停止"）

stores/multiAgent.ts：
- agent_start / agent_step / agent_stream 事件按 agent_id 归并进 agentsMap，
  作为 assistantMsg.agents 多面板数据源
- text_delta 真增量：主回答 += delta 逐 token 渲染；子 Agent 来源增量带 agent_id 并入其 parts
- 双事件源都有处理分支（§538-565）：(a) stream_events 真增量 message.part.delta 直通；
  (b) 前端 agent_stream / agent_done 事件 -> 归并
- 并行面板兜底：done 事件时若直播事件缺失（重连/丢帧），用后端 agents_snapshot 回填面板；
  去重渲染（单 Agent 路由且面板内容=最终答案时不重复展示）
- parts 累积辅助函数：appendAgentTextPart / appendAgentFinalText / appendAgentToolPart
  （对齐 opencode Part 排序；同 step_id 原位 upsert）
- 持久化：IndexedDB 防抖 1.2s + 终态立即冲刷 + migrateToServerId（防断连丢内容）；
  重试机制 S8 独立计数；[S2] client_msg_id 幂等
- 中断：abortController.abort() + interruptSession() 通知后端级联取消

组件：
- views/MultiAgentView.vue：加载历史 / 发送 / 排队提示 / 双击 Esc 取消
- components/MultiAgentResponse.vue：每个 Agent 一个面板（头像+名字+状态徽章+工具卡片+Markdown 正文）

## 8. 端到端时序（一次并行问答）

1) 前端 POST /multi-agent/stream（SSE 建立，收到 queued 位次）
2) endpoint 排队 -> Semaphore 放行 -> send_and_wait(AgentMessage chat)
3) SupervisorAgent.handle_message：_decompose() 判定
4) 多任务：gather 并行向 build/explore/plan 发子任务（独立 thread_id + 超时）
5) 子 Agent 事件经 TaggedEventQueue 透传 -> AgentEventCollector -> SSE 推送
   agent_start / agent_step / text_delta（真增量）
6) 前端 store 按 agent_id 归并 -> MultiAgentResponse 各面板实时渲染
7) 全部子任务完成：_synthesize() 汇总（多结果时）-> done 事件
   （含 answer / sources / agents_snapshot / tokens / 消息 id）
8) endpoint _persist_multi_agent 落库（主会话 + task 子会话）；前端 IndexedDB 同步

SSE 事件类型表：
- queued：排队位次（并发满时）
- routing：Supervisor 路由决定（快速路径/LLM/直连）
- agent_start / agent_step / agent_done：某子 Agent 生命周期与步骤（面板驱动）
- text_delta：主回答与子回答的真增量文本
- tool_heartbeat：>=3s 节流后的工具心跳（agent_step 形式，防 60s 停流误判）
- done：终态载荷（answer/sources/agents/tokens/消息 id）
- error：classify_error 分类后的错误载荷（可重试标记）
